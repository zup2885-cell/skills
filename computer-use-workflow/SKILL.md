# Computer Use 工作流程

这个 Skill 提供操作流程，依赖当前会话中实际可用的 Computer Use 工具。复制此文件夹不会安装插件、启用系统权限或修复连接。

## 选择工具和界面

- 优先使用能直接完成任务的专用连接器、API 或 CLI。需要视觉界面时使用 Computer Use。
- 用户指定浏览器、应用、标签页或网址时，按该目标选择界面。初始化时只执行工具说明允许的一项入口调用，读完返回的文档和状态再继续。
- 使用当前工具返回的 API 文档，不凭记忆调用旧接口。会话恢复后按工具要求重新获取文档。
- 只读取与任务有关的界面。优先选择已知目标；确实需要界面清单时才读取全局状态。

## 操作与验证

- 每个操作以刚读取的界面、可访问性信息或截图为依据。页面跳转、弹窗或提交后重新读取状态，避免使用过期坐标或元素。
- 表单内容依据用户资料和已读取的要求填写。缺少决定申请结果的必要信息时询问用户，继续完成不依赖答案的准备工作。
- 登录验证码、多因素验证和必须由本人完成的认证交给用户操作；不要求用户在聊天中发送密码或验证码。
- 用户已授权的动作在范围内继续执行；未获授权的发消息、发布、付款或申请提交，不因读取页面而自动获得授权。
- 提交后检查成功提示、回执或列表记录。仅点击按钮不能证明成功。结果不确定时先核实，避免重复提交。

## 安装与连接排查

- 分别报告：插件或应用是否存在、配置是否启用、工具能否连接、目标操作是否成功。
- 工具出现在会话中、安装文件存在或配置启用，都不能单独证明连接正常。
- 超时后记录失败步骤，按工具允许的方式重置一次并重试读取目标。相同超时再次出现时停止盲目重试，检查可用的插件诊断或本地运行状态。
- 不把连接失败直接归因于未安装或缺少权限。需要改变系统权限、配置或重启应用时，先确定依据和用户授权范围。
- 缺少相关工具时使用插件发现能力查找，不声称 Skill 本身可以提供桌面控制。

## GitHub 备份

- 备份本 Skill 文件夹；不上传应用二进制、会话状态、Cookie、令牌、用户配置文件或截图中的个人资料。
- 使用用户指定的仓库和路径；无法确定目的仓库时先准备本地内容，再询问目的地。
- 上传后读取远端文件核对内容，再报告同步完成。本地创建、远端保存和会话加载是不同状态，分别说明。

## 交付

简要说明完成了什么、验证依据以及尚需用户处理的阻碍。保留需要的回执或文件路径，避免在回复中泄露无关个人信息。

Skill 与插件的区别见 [OpenAI 官方说明](https://developers.openai.com/plugins/concepts/skills)。实际 Computer Use API 以当前工具返回的文档为准。
